# Grotto v1.8 — JUnit XML Adapter (Design)

Status: **shipped.** The third adapter, and the first new adapter since the v1.7
streaming seam — it validates that the registry generalizes (a 3rd adapter is one
file + one registry line) and that the buffered/file-reader shape (cargo's path)
generalizes to a non-cargo parser.

## Motivating evidence

`go test -json` (v1.6) and `cargo --timings` (v1.4) cover Go and Rust. JUnit XML is
the near-universal test-result format — pytest, jest (jest-junit), gradle, maven
surefire, ctest, cargo-nextest, gotestsum all emit it. One `junit` adapter is the
highest-leverage way to broaden reach beyond Go/Rust.

## Probe findings that shaped the design (verified on this machine)

1. **pytest 9.0.3 has no machine-readable JSON in core**, and neither streaming
   plugin (`pytest-reportlog`, `pytest-json-report`) is installed — adding one means
   a token-gated `pip install` plus a dependency every user needs. The one native,
   zero-dep option is `--junitxml`, which writes a single XML file at exit.
2. **`--junitxml` is a buffered/file-reader shape**, not a stream — so junit is a
   `CapturesStdout()==false` adapter like cargo, NOT a v1.7 `StreamAdapter`. (This is
   why the streaming-seam pitch didn't survive the probe; the buffered seam is the
   honest fit.)
3. **JUnit XML carries per-testcase *durations*, no start timestamps** — unlike cargo
   (start offsets) and go-test (absolute times). So a waterfall must *synthesize*
   left-to-right ordering; only the durations are real.
4. **pytest emits `<testsuites>` wrapping `<testsuite>`**; some runners emit a bare
   `<testsuite>` root. `encoding/xml` errors on an `XMLName` root mismatch (probed:
   "expected element type <testsuites> but have <testsuite>"), which the parser relies
   on — though the final design peeks the root with `xml.Decoder` for accurate errors.

## Ratified decisions

| Fork | Decision |
|------|----------|
| Path handoff (PrepareArgv → ParseSpans) | **ScratchDir in the contract.** `PrepareArgv` gains a `scratchDir` param + `BuildContext.ScratchDir`; grotto creates the per-run temp dir (it already does, for the socket/spool), injects `--junitxml=<scratch>/junit.xml`, and ParseSpans reads the same path. grotto owns the temp file (auto-cleaned with the run dir). (Rejected: a PID-derived temp path — a bespoke convention + manual cleanup, the "special case on shared infra" smell.) |
| Reach | **pytest-first, tight.** PrepareArgv injects `--junitxml` (pytest out of the box); ParseSpans reads universal JUnit XML. Other runners (jest-junit, gradle, maven, ctest, nextest) deferred to a future `--junit-file=PATH` passthrough. |
| Time model | Sequential layout: suites laid end-to-end from `StartNs`, testcases sequentially within a suite. Exact for serial pytest, approximate for parallel runners (xdist) — durations real, ordering synthesized. Trailing gap to `EndNs` = collection/startup overhead (shown by the existing gap pass). |
| Path ownership | grotto always controls the report path; a user-supplied `--junitxml` is stripped and **warned** (not silently dropped) so a CI-artifact path isn't lost without notice. |

## Architecture

- `internal/adapter/adapter.go`: `PrepareArgv(argv, scratchDir)`, `BuildContext.ScratchDir`, registry `"junit"`.
- `internal/adapter/junit.go`: `junitAdapter` (buffered, `CapturesStdout()==false`).
  `parseJUnit` peeks the root via `xml.Decoder` (local-name match → namespace-tolerant)
  and dispatches to `<testsuites>` or `<testsuite>`; `suitesToSpans` lays the
  sequential waterfall and clamps every bound into `[StartNs, EndNs]`.
- `internal/collect/marks.go`: the run temp dir is created **before** `PrepareArgv`
  (so the scratch path exists) and passed both to `PrepareArgv` and via
  `BuildContext.ScratchDir`. cargo/go-test ignore the new param.

## Edge cases / failure modes

- **Missing report** (crash before flush / runner ignored the flag) → `(nil, nil)`,
  degrade to the opaque root span (cargo's contract).
- **Malformed report** → error (collect warns, base trace stored). `xml.Decoder`
  surfaces the real child error, not a misleading root-mismatch one.
- **Unexpected root** (`<results>` etc.) → explicit error.
- **Absurd/NaN `time`** → `secondsToNs` floors ≤0/NaN to 0 and caps at ~285 years so
  `sec*1e9` can't overflow int64; clamp bounds the span regardless.
- **Suite with a failing/erroring case** → suite carries error status; `<skipped>` is
  not a failure (ok status, matching the go-test adapter).

## v1.8 cut line / deferred (from the v1.8 code review)

In scope: the `junit` adapter (pytest via `--junitxml` injection, universal XML
parse), the ScratchDir contract addition, sequential layout, root-peek parse,
strip-with-warning.

Deferred (noted, not built): a `--junit-file=PATH` read-existing-file mode for any
JUnit-emitting runner (the true "universal" mode); extracting shared `clamp`/
`secondsToNs` helpers once a 4th adapter lands (don't refactor working cargo now); a
`PrepareOptions` struct if `PrepareArgv` grows more per-run inputs; `ScratchDir` on the
streaming path (no consumer yet); capturing `<failure message>` to show *why* a test
failed (needs span attributes for buffered adapters).

## Verification plan

- Unit: PrepareArgv injection + strip (both spellings, both `=value`/separate-token
  forms); parse layout + nesting + sequential timing; failure/skip status + bare
  `<testsuite>` root; missing-report benign; malformed + unexpected-root error.
- Integration/dogfood: `grotto run --adapter=junit -- python3 -m pytest` on a real
  suite; confirm per-test waterfall + the strip warning fires on a user `--junitxml`.
- Gates: `CGO_ENABLED=0 go build ./...` · `go test ./...` · `golangci-lint run ./...`
  · `/code-review` before merge · tagged release with static binaries + checksums.

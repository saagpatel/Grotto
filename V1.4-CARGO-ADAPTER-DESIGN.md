# Grotto v1.4 — Cargo Build Adapter (Design)

**Status:** Design ratified 2026-06-06. Not yet implemented. Execute from this spec.
**Headline:** `grotto run --adapter=cargo -- cargo build` turns an opaque 45s build bar into a
per-crate waterfall, by ingesting cargo's own `--timings` report.

## Motivating evidence
Cold 715-crate Tauri build (JobCommandCenter): total 56.31s, the `build` phase was 81%
(45.57s) as **one opaque bar** — `grotto mark` can't reach inside cargo's compile loop.
`grotto diff` vs warm rebuild quantified the cache at 56.31s→2.75s. The adapter is what turns
"useful if you instrument" into "point it at any build and *see*."

## Probe findings that shaped the design (verified on cargo 1.96.0, stable)
1. **`cargo build --timings=json` does NOT exist on stable** — errors `unexpected value 'json'`.
   The `=json` form is nightly-only (`-Zunstable-options`). The handoff's premise was wrong.
2. **Plain `--timings` (stable since 1.60) writes an HTML report** embedding the real data as a
   JSON array, `const UNIT_DATA = [...]`. Per-unit schema:
   ```json
   { "i":0, "name":"itoa", "version":"1.0.18", "mode":"todo",
     "start":0.22, "duration":0.08,          // seconds, 2-decimal (10ms) precision
     "unblocked_units":[...],                  // crate-DAG edges
     "sections":[ ["frontend",{"start":0.0,"end":0.06}],
                  ["codegen", {"start":0.06,"end":0.08}] ] }
   ```
3. **Cargo announces the path on stderr:** `Timing report saved to <absolute-path>.html`.
   Robust locator — survives `CARGO_TARGET_DIR` / workspace target layouts. No globbing.

## Ratified decisions
| Fork | Decision | Why |
|------|----------|-----|
| 1. Data source | **Stable `--timings` HTML → parse `UNIT_DATA`** | Real start+duration with parallelism baked in. stderr `Compiling` gives only starts → durations are fiction under concurrency. `=json` would force a nightly toolchain and gut "any build". |
| 2. Aggregation | **`GapMinNs` threshold + top-N cap + rollup bucket, render-only** | Extends grotto's existing "≥1 timeline char" instinct to content. Total stays accounted (bucket carries summed leftover); never silently dropped. |
| 3. Invocation + seam | **Explicit `--adapter=cargo`, minimal `Adapter` interface + map registry** | Flag value *is* the registry key. Auto-detecting "is this cargo" is fragile (test/clippy/+nightly/wrappers). No plugin framework for one consumer. |

## Why the data model already fits (no new structural concepts)
`assembleTrace` derives each span's `EndedNs` from neighbors, and `InsertGaps`' cursor does
`max(EndedNs)` — **grotto's span model already tolerates overlapping intervals.** Concurrent
crate compiles → overlapping `[start, start+duration]` windows → overlapping bars, natively.

Mapping `UNIT_DATA` → spans (anchored to grotto's `startNs`):
- `StartedNs = startNs + round(start * 1e9)`
- `EndedNs   = StartedNs + round(duration * 1e9)`
- `Name = fmt.Sprintf("%s v%s", name, version)`, `Kind = KindInternal`, `Status = StatusOk`
- `ParentSpanID = rootID` (flat per-crate for v1.4)
- `sections` (frontend/codegen) maps onto grotto's existing **one-level `--child` nesting** —
  deferred to v1.5, not built now.

**Free win:** cargo's t=0 is after grotto's `startNs` (process spin-up + manifest resolve +
fetch). Anchoring crate spans to `startNs` leaves that pre-first-crate stretch as a leading
`(gap)` via the existing `InsertGaps` logic — cargo's own resolve overhead, made visible. Feature,
not bug.

## Architecture

### Adapter interface (`internal/adapter/adapter.go`)
```go
type Adapter interface {
    Name() string
    // PrepareArgv injects flags the adapter needs (cargo: ensure --timings present,
    // idempotent — no double-inject if the user already passed it).
    PrepareArgv(argv []string) []string
    // ParseSpans runs after the command exits. Returns child spans parented under
    // rootID, anchored to startNs. MUST tolerate missing artifacts (failed build may
    // emit no report) by returning (nil, nil) — degrades to today's opaque root span.
    ParseSpans(ctx context.Context, rootID, traceID string, startNs, endNs int64, stderr []byte) ([]model.Span, error)
}

var adapters = map[string]Adapter{"cargo": cargoAdapter{}}  // registry == pluggability
```
Adapter #2 (`go test -json`, pytest) is a one-file add to this map. No discovery, no framework.

### Cargo adapter (`internal/adapter/cargo.go`)
- `PrepareArgv`: append `--timings` if absent. Scope v1.4 to `cargo build` / `cargo test`
  (subcommands that accept `--timings`); document the boundary.
- `ParseSpans`:
  1. Grep captured stderr for `Timing report saved to <path>`; if absent → return `(nil, nil)`.
  2. Read file, slice `const UNIT_DATA = [` … matching `];`, `json.Unmarshal` into `[]unit`.
  3. Map each unit → `model.Span` per the formula above. Return them.
- **Pure stdlib only** (`strings`, `encoding/json`) — no new deps, no HTML parser, no cgo.
  Respects the `CGO_ENABLED=0` hard gate.

### `internal/collect` integration (`marks.go` Run + cmd plumbing)
- `Run` gains an optional `adapter Adapter` param (or a variant `RunWithAdapter`).
- When an adapter is active: `argv = adapter.PrepareArgv(argv)`, and **tee stderr** —
  `cmd.Stderr = io.MultiWriter(os.Stderr, &stderrBuf)` so the user still sees cargo's output
  live while we capture it for the report-path line. (Current code wires `cmd.Stderr=os.Stderr`
  directly; this is the one plumbing change.)
- Order after exit: `assembleTrace(...)` (yields rootID, startNs, endNs) →
  `adapter.ParseSpans(rootID, ...)` → `spans = append(spans, adapterSpans...)` → recompute
  `SpanCount` → `InsertTrace`. Adapter spans coexist with any marks (both are root children).
- `Trace.Source = "cargo"` (vs `"mark"`).

### Render aggregation (`internal/render/`, new pass alongside `InsertGaps`)
**Store all crate spans canonically** (715 spans/trace is fine for SQLite) — aggregation is
**render-only**, same discipline as gaps. New pass, e.g. `RollupBelowThreshold(root, minNs, cap)`:
1. Among a parent's children, keep those with `DurationNs >= GapMinNs(rootDur, width)`.
2. Hard-cap kept set to top-N by duration (N = terminal height budget or a `--limit` flag) so a
   huge build can't overflow the screen.
3. Collapse all excluded crates into one synthetic `(N crates < threshold)` leaf carrying the
   **summed self-time**, namespaced span ID like gap nodes (`rollup:<parent>:<idx>`).
- Composes with `InsertGaps`. Like gaps, **not** applied to `grotto diff`.

**As built (v1.4):** shipped as `render.RollupExcess(root, DefaultMaxRows=25)` — **cap-primary**, not
threshold-on-content. A parent with ≤ `maxRows` real children is left byte-identical (so no existing
trace's render changes); over the cap, the top `maxRows-1` by duration are kept and the long tail
collapses into one `(+N more)` bucket (union interval for the bar, **summed** self-time for the
number, error status propagated so a hidden failed unit can't vanish). The `GapMinNs` threshold keeps
doing its job in the gap pass; folding a content-threshold into the cap is deferred — the cap alone
solves the 700-row problem and is lower-risk. Verified end-to-end on a cold 40-crate build: 41 spans
stored, 24 dominant + bucket + leading gap rendered.

## Edge cases / failure modes
- **Build fails** → cargo may write no report → `ParseSpans` returns `(nil,nil)` → root span only
  (today's behavior). Root status = error from non-zero exit, unchanged.
- **`--timings` already present** in user argv → don't double-inject.
- **Non-build subcommand** (`cargo clean`) → `--timings` rejected by cargo; document v1.4 scope as
  build/test. Loud cargo failure is acceptable.
- **2-decimal (10ms) precision** → sub-10ms noise sits below the render threshold by construction.

## v1.4 cut line
**In:** stable-HTML adapter, flat per-crate spans, threshold+cap+bucket render-only pass,
explicit `--adapter=cargo`, `Adapter` interface + registry, stderr tee.
**Deferred to v1.5:** frontend/codegen `sections` sub-nesting; **critical-path view** through the
crate DAG via `unblocked_units` (the genuinely-differentiated "where did 45s actually go" answer);
second adapter (`go test`/pytest); `--adapter=auto` sniff layered on top of explicit.

## Emergent win (free, from storing real spans)
`grotto diff` cold-vs-warm already works on stored spans → **per-crate cache deltas** fall out
with zero extra work once crate spans are persisted. Strong v1.5 demo.
